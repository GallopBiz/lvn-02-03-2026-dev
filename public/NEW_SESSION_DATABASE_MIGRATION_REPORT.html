New Academic Session Database Migration Report

System: LVN Multi-Database School Management System

Database Transition: 2025_2026 (Source) → 2026_2027 (Target)

Generated Date: October 2026 | Total Tables Analyzed: 169 Tables

Architecture Notice: The LVN School ERP operates on a Database-per-Session model. When an administrator switches the academic year in the UI, the dynamic connection rebinds to that session's database (e.g. 2026_2027). Consequently, creating a new session requires instantiating a complete schema with all 169 tables, but populating them according to strict classification rules.

1. Core Dependency Flow (What Must Exist First)

Before standard school operations can proceed in the new session, tables must be set up in the following order:

Order Layer Required Tables Operational Impact
1 System & Auth users, roles, permissions, model_has_roles, role_menus Enables administrator and staff login; allows navigation into the new session.
2 Academic Structure class_name, sections, streams, subjectmaster, caste_name Populates class, section, and subject dropdowns across all modules.
3 Staff & HRMS hrms_employees, teachers, hrms_departments, hrms_positions Enables class-teacher assignment, subject allocation, and staff biometric logging.
4 Fee Configuration fees_types_master, course_fees_structure_master, schedulemaster Defines fee heads, class-wise fee amounts, and installment deadlines for due charts.
5 Transport Setup vehicel, busstop, routemaster, busfees, busstaff Enables bus route assignments and transport fee calculation.
6 Student Master student_registration Core entity: required before generating fee bills, roll numbers, attendance, or marks.

2. Data Classification Matrix

Category A Copy As-Is (Data + Schema)

Master settings, lookups, and configuration that remain identical across sessions:

  • Auth: users, roles, permissions, role_menus
  • Academic: classes, class_name, sections, streams, subjectmaster, grades
  • Demographics: caste_name, states, cities
  • Transport: vehicel, busstop, routemaster, busfees
  • Staff: hrms_employees, employee profiles, salaries
  • Fee Setup: fees_types_master, course_fees_head_master

Category B Promote / Migrate Selectively

Data carried forward with updated status or incremented class:

  • Students: Promote via StudentTransferController:
    • Increment class (Nursery → KG1 → ... → 12)
    • Skip Class 12 (graduated)
    • Exclude TC issued (status = 't')
    • Retain repeaters (next_year == 1)
  • Arrears: Pending balances → student_fee_balances
  • HRMS Loans: Carry forward active unpaid EMIs only
  • Calendar: New holiday list in hrms_holidays

Category C Fresh / Zero Records (Structure Only)

Operational and transaction tables that MUST be empty (0 rows) at session launch:

4. Pre-Launch Verification Checklist

  • [ ] Database Switching: Log into admin panel, select 2026_2027 in the session dropdown, and verify no DB connection errors occur.
  • [ ] Student Promotion: Run Student Transfer for classes Nursery to 11. Confirm Class 12 students and TC-issued students are excluded.
  • [ ] Fee Chart Initialization: Review updated installment dates in schedulemaster and generate student due charts.
  • [ ] Zero-Transaction Integrity: Verify that tables like feesreceiptchallan and academic_attendance have 0 rows.
  • [ ] Teacher Assignment: Map teachers to new classes using classasigntoteacher.
